# 任务中心

这个目录用于存放所有已完成或进行中的**持久化任务档案**。每个复杂任务都会在这里创建一个独立的文档文件，作为该任务的**唯一事实来源 (SSOT)**。

## 目录结构

```
tasks/
├── README.md                           # 本文件，任务中心说明
├── task_YYYYMMDD_[简短任务描述].md      # 具体任务档案
└── archived/                           # 已归档的历史任务
```

## 任务文件命名规范

- **格式**: `task_YYYYMMDD_[简短任务描述].md`
- **日期**: 任务创建日期，格式为 YYYYMMDD
- **描述**: 简短的任务描述，使用下划线连接单词
- **示例**: 
  - `task_20240115_database_integration.md`
  - `task_20240116_user_registration_api.md`
  - `task_20240117_docker_deployment.md`

## 任务状态

每个任务文件都应该包含明确的状态标识：

- **pending**: 任务未开始
- **in_progress**: 正在进行中
- **completed**: 已完成
- **blocked**: 被阻塞，需要外部输入
- **cancelled**: 已取消
- **archived**: 已归档

```markdown

**创建时间**: YYYY-MM-DD

**完成时间**: YYYY-MM-DD
**负责人**: [AI/User]
**优先级**: [高/中/低]

## 目标
[描述最终要达成的业务或技术目标]

[任务产生的背景和原因]
```

## 任务管理流程

### 1. 任务创建
- 当遇到复杂任务时，在此目录创建新的任务文档
- 使用标准模板填写任务信息
- 设置任务状态为 `pending`

### 2. 任务执行
- 将任务状态更新为 `in_progress`
- 按照执行步骤逐步完成任务
- 及时更新步骤完成状态 (`- [ ]` → `- [x]`)
- 记录遇到的问题和解决方案

### 3. 任务完成
- 将任务状态更新为 `completed`
- 填写完成时间
- 进行经验总结
- 更新相关的基线文档

### 4. 任务归档
- 完成的任务可以移动到 `archived/` 目录
- 保留任务文档作为历史记录
- 重要经验沉淀到项目规则中

## 任务类型

### 功能开发任务
- 新功能的设计和实现
- API 端点的开发
- 数据模型的创建

### 架构优化任务
- 代码重构
- 性能优化
- 架构调整

### 基础设施任务
- 开发环境配置
- 部署流程建立
- 监控系统搭建

### 文档维护任务
- API 文档更新
- 技术文档编写
- 用户指南制作

## 最佳实践

### 任务粒度
- 单个任务应该在 1-3 天内完成
- 过大的任务应该拆分为多个子任务
- 每个任务都应该有明确的交付物

### 状态更新
- 及时更新任务状态和进度
- 遇到阻塞及时记录和寻求帮助
- 完成后及时进行总结

### 知识沉淀
- 重要的技术决策要详细记录
- 问题和解决方案要完整描述
- 经验教训要及时总结和分享

### 协作沟通
- 任务文档是团队协作的重要工具
- 保持文档的及时性和准确性
- 重要变更要及时通知相关人员
